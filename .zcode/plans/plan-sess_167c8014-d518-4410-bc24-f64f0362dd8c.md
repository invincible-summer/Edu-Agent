# 教材解析并行化优化方案（质量与解析方式零改变）

## 核心原则

同样的 prompt、同样的逐章/逐卷输入、同样的确定性合并与写盘逻辑、同样的 OCR 逐页结算/断点恢复/重试语义——**只改变独立调用的执行调度（时间上重叠）**。并新增「原有串行方式」开关（legacy 模式下执行顺序与现状完全一致），全部参数管理员界面可在线调整。

## 四项并行化

1. **逐章概念抽取并行**（单书最大头：一本书 15~61 次 LLM 调用目前顺序 await）
2. **跨书构建并行**：per-owner 队列从严格串行改为有界并发——书 B 的 OCR 与书 A 的概念抽取重叠（正是你要的场景）
3. **组内多卷并行**：多卷组 B 卷 OCR 与 A 卷抽取重叠
4. **图表图述并行**：每卷最多 40 次视觉调用目前逐个 await

OCR 逐页本身已并行（全局 20~30 页上限），不动。

## 已验证的安全性依据（为什么结果不变）

- 章间零依赖：每章 prompt 只依赖（章名、章文本、subject/level），且 subject/level 在循环前定死（textbook_builder.py:2012-2018）→ 保序并行结算与串行逐项产出一致
- 卷间独立：各卷有独立 .txt / OCR state / volume_spec 缓存；合并是确定性纯函数且按卷序执行
- 状态写入（`update_textbook`/`_save`/`_write_text_and_chunks`）均为无 await 的同步函数，单事件循环内天然原子，多书并行不会互相覆盖
- 全局限流保留并升级为可在线调整；取消/删除守卫逐章逐卷保留

- `_LLM_SEMAPHORE`(L54) 的 4 处使用点（L956/L1016/L1143/L1198）改用动态门 `textbook_pipeline.llm_gate()`

## 预期收益

- 单书：章节抽取阶段约 4×（稳健档 LLM 并行 4）；OCR 阶段不变（本就受全局页上限并行，管理员可在现有 OCR 策略页再调高）
- 排队多书：书 B 的 OCR 与书 A 的抽取重叠，墙钟时间约减半起步
- 多卷组：卷间 OCR/抽取重叠；图述阶段数分钟级缩短
- 全部参数运行时可调，可一键切回原有串行方式
